# X-T30 III 真机验证清单

截至本提交，**没有任何功能在 X-T30 III 上验证过**。

请按顺序执行本清单。每通过一项，在 `FujiKit/Sources/FujiKit/Capabilities/CapabilityCatalog.swift` 中给对应条目的 `statuses` 加上 `.deviceVerified`，把 `camera`/`evidence` 改为实测结果（写上固件版本），再按 README 中的命令重新生成 `docs/CAPABILITY_MATRIX.md`。

## 准备

- **相机**：
  - 记录机身固件版本，在相机菜单 → 设置 → 用户设置 → 固件版本 中查看。
  - 电池充满。
  - 使用**测试用的 SD 卡**，放入几种文件：JPEG、HEIF（如机身支持）、RAF、JPEG+RAF、短视频、一张超过 20 MB 的文件。
- **iPhone**：iOS 27。按 README 构建，用 Debug 构建运行。
- **App**：在“设置 → 诊断”中打开“详细协议日志”，在“设置 → 传输”中打开“记录下载前后的相机属性”。
- **对照数据**：用读卡器把 SD 卡上的原文件复制到电脑，计算 SHA-256，例如运行 `shasum -a 256 DSCF*.*`。
- 每完成一个阶段，在“设置 → 导出脱敏诊断日志”中导出一次日志并保存。日志中不含 Wi-Fi 密码、令牌、序列号；**提交日志前仍请自己检查一遍**。

本清单**不包含**删除照片、恢复设置、固件更新。App 也没有实现这些功能。

## 3. 图库与传输

| # | 步骤 | 记录 | 通过标准 |
|---|---|---|---|
| 3.1 | 图库列表 | 对象数量；JPEG/HEIF/RAF/视频各自是否出现 | 与 SD 卡内容对照，**逐种格式**记录是否出现在 Wi-Fi 列表 |
| 3.2 | 缩略图 | 是否都有缩略图 | 显示正常 |
| 3.3 | 下载 JPEG（关闭“缩小”） | SHA-256（图库 → 照片详情 → “文件”分区，可选中拷贝） | **与读卡器得到的 SHA-256 完全一致** |
| 3.4 | 下载 RAF、HEIF、视频（如果在列表中） | 同上；完整性检查结果 | 逐一比对一致。不一致或检查失败时记录日志 |
| 3.5 | 开启“缩小”后下载同一张 JPEG | 日志中下载前后的 D226/D227；文件尺寸和分辨率 | 记录 D226 的实际效果；文件被标记为“相机缩小版”，与原图区分 |
| 3.6 | 下载大文件时关闭相机 Wi-Fi 或走出覆盖范围，然后恢复 | 日志中的续传校验结果（偏移、64 KB 比对） | 从断点续传；如果对象身份或数据不一致，从头下载。最终 SHA-256 一致 |
| 3.7 | 重复下载同一文件 | — | 图库中标记为已导入，下载前提示“部分文件此前已导入”；强制重新下载时，内容相同（SHA-256）的文件不会保存第二份 |
| 3.8 | 存入照片 | 在照片 App 中导出原件，计算 SHA-256 | 与原文件一致（没有重新编码） |
| 3.9 | 多选 20 张下载时切到后台 | 是否出现系统进度（BGContinuedProcessingTask）；时间到后的状态 | 回到前台后能继续，已下载的部分不丢失 |
| 3.10 | 在相机上选图后发送（如果相机支持） | 相机状态 DF00 是否为 1（多张传输） | 记录相机推送的文件能否进入传输队列 |
